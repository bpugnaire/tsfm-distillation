Inside the student: one forecast, step by step

In short
  • The student is a small patch transformer. It cuts 512 steps into 32 patches of 16, adds one learned query token, runs 4 transformer layers, and reads all 64 forecast steps and 13 quantiles off that token in one pass.
  • Three numbers fix its range: the position table (33 rows) caps the input at 32 × 16 = 512 steps, and the output layer (832 = 13 × 64 outputs) fixes the horizon and the quantile levels. The amplitude has no limit: the scaler handles it.
  • Knowledge is in the weights: 56% in the feed-forward blocks, 28% in attention. Nothing about a particular series is stored; everything comes from the 512 input values at inference time.
  • Measured levers: more training windows, a bigger network (−7% error from 0.22M to 0.95M), longer context on some data. Not yet tested: covariates, several series at once.

2. What fixes the range of inputs and outputs

A forecaster has limits set when it is built: how far back it reads, how far ahead it predicts, and which quantiles it gives. In this model each limit is one specific tensor. Changing a limit means changing that tensor's shape, which means retraining.

The amplitude is not a limit. The scaler re-centres and rescales every window, so the network always sees numbers of the same size. We checked this on the trained model: multiply the input by 1,000 and add 50,000, and the forecast moves the same way, to within of the series' scale. Floating-point rounding accounts for the rest.

3. Where the knowledge lives

  • Feed-forward blocks hold most of the weights. They transform each token on its own. Interpretability work on language models finds learned patterns stored there (Geva et al., 2021); here those are patterns like cycles, trends continuing, what follows a spike.
  • Attention decides which past patches each token reads. It is the routing. Step 5 below shows where the query token looks on a real series.
  • The query token is 128 learned numbers that work like a question. Its starting value is the same for every series. Layer by layer, attention fills it with what the forecast needs, and it is the only token the head reads.
  • The head turns that 128-number summary into 13 × 64 values. 11% of the model is spent on this one layer, and its size grows with the horizon.

There is no memory of past series. Each forecast is computed from the 512 input values and the weights, then thrown away. That is why the model works on series it has never seen, and why it cannot use anything further back than 512 steps.

5. Why this architecture

  • Patches, not single steps. Attention compares every token with every other one, so its cost grows with the square of the token count. 33 tokens cost about 240 times less than 512. One patch of 16 hours is also a meaningful unit: part of a day. Patching comes from PatchTST (Nie et al., 2023) and is used by most forecasting foundation models.
  • One query token, one pass. The model predicts all 64 steps at once. Many large models instead feed each prediction back in as input to get the next one. One pass is what makes a forecast take 0.75 ms (post 5).
  • A mask channel. Each patch carries 16 values and 16 "observed" flags. Missing values and left padding need no special code: the model learns to ignore flagged-out steps.
  • Pre-norm layers (LayerNorm before attention and before the feed-forward block) are the standard choice for stable training since GPT-2.
  • Quantiles that cannot cross, by construction (step 7 above), and the scaler inside the model, so the browser sends raw values (post 5).

To be clear about evidence: we did not compare this architecture against alternatives in this project. We did measure its size (section 6). The defaults follow what works in the published foundation models, scaled down.

6. Where to improve it

For a new use, the order to try is: more training windows on inputs like yours, then a longer context if your series has long cycles, then a bigger network.

Checklist

  • Context = patch length × number of patches: choose both together. A longer context with a longer patch keeps the cost the same.
  • The head size is horizon × quantile levels × width. Decide the horizon before training.
  • Standardise each window inside the model, so amplitude is never a limit.
  • Give the network a mask channel instead of filling missing values.
  • Read the forecast from one query token. Predict all steps in one pass.
  • Build the quantile head so quantiles cannot cross.
