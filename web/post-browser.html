Running the model in a browser tab

In short
  • npm install onnxruntime-web, import onnxruntime-web/wasm; Vite bundles the WebAssembly binary for you.
  • Send a Float32Array with NaN for missing values; the scaler inside the graph handles them.
  • Time only session.run, after a warm-up call, and report the median.
  • Never queue inferences: run one at a time, and only on the latest input.

Points worth copying:

  • Import the WASM build (onnxruntime-web/wasm), not the default entry, when you do not need WebGPU. Vite resolves the .wasm file through import.meta.url, so there is no CDN and no manual copy step.
  • Threads need cross-origin isolation. Multi-threaded WASM requires the COOP and COEP HTTP headers. GitHub Pages does not send them, so we set numThreads = 1 unless self.crossOriginIsolated is true. A one-millisecond model does not need more.
  • Pad on the left with NaN. The model reads exactly 512 values. Shorter inputs are left-padded with NaN, and gaps in the drawing stay NaN. The graph's mask channel ignores them.
  • The output is flat. quantiles.data is a Float32Array of shape (1, 13, 64) in row-major order: slice it per quantile level.

2. Measure latency honestly

The first session.run compiles kernels and is much slower than the rest. Run it once on dummy data inside load() and never time it. Then time session.run alone with performance.now(): no drawing, no array copies. Keep the last 50 timings and show the median, not the mean: garbage collection and tab throttling produce rare, huge outliers. The demo's readout does exactly that, on your machine, live.

For reference, on an Apple M1 Pro the same file runs in 0.75 ms per forecast in ONNX Runtime for Python, one thread (results/shapes/student-toto-onnx-fp32.json). The browser number depends on your machine and browser; compare it with the live readout in the demo.

3. Drive it from a canvas without lag

The demo forecasts on every pointer move. Pointer events arrive faster than any model, so naive code queues hundreds of inferences and the forecast trails the pen. The fix is a dirty flag and one inference in flight:

let busy = false, dirty = false;
const request = () => { dirty = true; requestAnimationFrame(() => void pump()); };

async function pump(): Promise<void> {
  if (busy || !dirty) return;      // one inference at a time
  dirty = false;
  busy = true;
  try { forecast = await model.forecast(values.slice(0, origin + 1)); }
  finally { busy = false; }
  render();
  if (dirty) requestAnimationFrame(() => void pump());   // input changed meanwhile: run once more, on the latest
}

Two details of the drawing itself. Pointer events skip time steps when the pen moves fast, so fill every step between two events by linear interpolation. And treat the pen tip as "now": erase everything to its right when the user draws backwards, otherwise old strokes leak into the context.

if (prev) {                                   // fill the steps between two pointer events
  const [i0, v0] = prev;
  for (let k = Math.min(i0, i); k <= Math.max(i0, i); k++)
    values[k] = i === i0 ? v : v0 + ((v - v0) * (k - i0)) / (i - i0);
} else values[i] = v;
for (let k = i + 1; k < values.length; k++) values[k] = NaN;   // the pen tip is the present

4. Draw the uncertainty, not just the line

The fan chart is three d3.area() bands between symmetric pairs of quantiles (1–99%, 10–90%, 30–70%), from light to dark, with the median on top. Label what the bands are: "98%, 80% and 40% intervals" tells the reader how to use them; "likely range" does not.

import { area } from "d3-shape";
for (const [lo, hi, opacity] of [[1, 99, 0.14], [10, 90, 0.26], [30, 70, 0.42]])
  svg.append("path")
    .attr("d", area<number>().x((_, i) => x(origin + 1 + i)).y0((d) => y(d)).y1((_, i) => y(q[level(hi)][i]))(q[level(lo)]))
    .attr("fill", studentColour).attr("opacity", opacity);

Import only the D3 modules you use (d3-scale, d3-shape, d3-selection), not the d3 bundle.

Checklist

  • Preprocessing inside the ONNX graph; the browser sends raw values with NaN for gaps.
  • onnxruntime-web/wasm bundled by Vite; one thread unless the page is cross-origin isolated.
  • Warm-up run at load; time session.run only; show the median.
  • One inference in flight, re-run only on the latest input.
  • Fan chart with labelled intervals.
